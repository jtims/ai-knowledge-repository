**Capability:** Surface: the Claude Code desktop app's built-in browser pane (tools mcp__Claude_Browser__*), operating a published claude.ai artifact. When the pane is signed in to a claude.ai account (the owner's in every recorded run; observed 2026-09-22 and 2026-09-23; whether the sign-in persists is UNKNOWN) and the artifact's in-page consent stands on that account (recorded for the Cover Letter Desk in session 6, in two wordings; see the caveats), Claude can open that account's own private artifact there, paste into and press its controls by screen coordinates, read the page from screenshots, and trigger the in-page Claude call the page declares under the sample capability, which then runs on that account's plan.

**What it unlocks:** A cheaper path than the obvious one for proving an agentic artifact build: no person operates the page or relays its output (speed against a person-operated run was not measured). The obvious path is a person operating the page: during the bake-off the desk ran in the owner's own tab (WORKLOG line 131). With the pane signed in, Claude closes the build, live-run, read and revise loop inside one Claude Code session, with no API key, no separate person operating the page and no inspection access into the frame: navigate to the published page, paste the input, press Analyze and then Draft at the default ticks, and read the output before the owner exports or sends anything. It changed a build decision: the Cover Letter Desk was proof-run by Claude, not by a person, and run 1's findings drove desk v2.3. Graded `accelerates`, not `unlocks`: by house rule (the owner project's desk-test README) the owner still approves every run because it spends his usage, and pressing controls by coordinates through a cross-origin frame is ordinary for a screenshot-driven agent and is the workaround CLD-C033 names; the non-obvious half is that Claude's coordinate presses through the cross-origin frame are accepted as the viewer's own and fire the sample call ([[CLD-CAP008_artifact-sample-capability-asks-claude-on-the-viewers-plan|CLD-CAP008]]) on the pane's account, with no key and no API. A screenshot read does not have to be trusted alone: a transcription is verifiable against the page's own meter, recomputed from the page code (procedure in the owner project's desk-test README). Proven live twice in owner session 6 on one artifact, the Cover Letter Desk (desk v2.2 and v2.3; both transcriptions matched the meter exactly; run 1 partial, run 2 near parity); the signed-in and render precondition was re-confirmed live on 2026-09-23 in a probe that made no call.

**Caveats & linked constraints:** Coordinates and screenshots are the only proven route: the artifact page is a cross-origin frame, and on 2026-09-23 read_page and find listed no desk control, javascript_tool found the artifact frame's contentDocument null, and get_page_text returned only the host page's text ([[CLD-C033_artifact-frame-is-cross-origin-to-browser-pane-tools|CLD-C033]]). The call this triggers is the sample capability ([[CLD-CAP008_artifact-sample-capability-asks-claude-on-the-viewers-plan|CLD-CAP008]]), not a second call surface, and it is bounded to a tier with no model ID, no effort setting and no memory between calls ([[CLD-C032_artifact-sample-call-exposes-model-tier-only|CLD-C032]]); the page has no outbound network beyond its own published files and the sources its contract allows, so input still arrives by paste, file pick, the artifact database or a connector, and here it was pasted ([[CLD-C031_artifact-page-network-is-blocked|CLD-C031]]). The session 6 records word consent differently: WORKLOG line 128 (and the project memory written at the session 6 close) say "consent already granted there", and Bake-Off section 10 says "the owner approved the consent step and the usage". Whether a consent prompt appeared in the pane during the runs, and who cleared it, is UNKNOWN; the per-call consent rule is in CLD-CAP008. Each run spends the owner's claude.ai usage and, by house rule (the owner project's desk-test README), needs his approval each time; neither proof run exported or sent anything, and export through this route was not tested. The sign-in is a state observed on 2026-09-22 and 2026-09-23, and the consent state one recorded on 2026-09-22 only, in the two wordings above; neither is a documented guarantee. Proven live: the two session 6 runs; the call itself was not re-run on 2026-09-23. UNKNOWN, never tested against this frame in any session: the Chrome extension's tools (`mcp__claude-in-chrome__*`) and the form_input tool; the Artifact tool's own read, recorded as returning the published source rather than the live DOM, was also not tested, so none of the three is a known substitute for the coordinate and screenshot loop.
