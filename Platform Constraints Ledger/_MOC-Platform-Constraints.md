## Design-invalidating quick sheet (the never-assume list)

- **[[LOV-C001_no-supabase-dashboard|LOV-C001]]** no Supabase dashboard on Lovable Cloud
- **[[LOV-C002_no-service-keys-no-external-db-access|LOV-C002]]** no service keys — external tools can't reach Lovable Cloud DBs
- **[[LOV-C004_edge-fns-dont-redeploy-on-git-push|LOV-C004]]** git push ≠ fn deploy
- **[[LOV-C006_knowledge-and-skills-dont-enforce|LOV-C006]]** Lovable knowledge/skills never enforce
- **[[LOV-C010_connector-removal-is-org-wide|LOV-C010]]** connector removal is org-wide
- **[[LOV-C014_remix-regenerates-generated-files|LOV-C014]]** remix regenerates client.ts/types.ts — never put app-owned symbols in generated files
- **[[LOV-C015_grant-hardening-resets-on-remix|LOV-C015]]** DB grant/RLS hardening resets on remix — clone security ≠ template security; re-apply per clone
- **[[LOV-C016_workspace-default-template-not-applied-on-mcp-path|LOV-C016]]** a workspace DEFAULT template does not reach the MCP `create_project` path, and no MCP field reveals it — pass `template_project_id` explicitly, always
- **[[LOV-C017_bare-mcp-create-returns-different-framework|LOV-C017]]** a bare `create_project` returns TanStack Start — a DIFFERENT framework from a Vite template, so "add governance later" is a migration, not a copy
- **[[LOV-C018_initiate-project-cannot-scope-or-template|LOV-C018]]** `initiate_project` cannot be workspace-scoped or templated, and appears in NO vendor doc — prohibit it by name
- **[[LOV-C022_transfer-breaks-sync-and-reconnect-creates-new-repo|LOV-C022]]** on a Lovable-synced repo the destructive op is TRANSFER, not rename (rename is safe on GitHub, breaking on GitLab), and disconnect-and-reconnect is the DESTRUCTIVE repair: it always creates a new repository and the old one can never be re-linked. Reverse the originating operation instead
- **[[N8N-C001_webhooks-unauthenticated-by-default|N8N-C001]]** bare n8n webhooks are open doors
- **[[CLD-C001_description-hazard-chars-break-frontmatter-parsing|CLD-C001]]** a YAML parse is NOT proof an agent registered
- **[[CLD-C003_workflow-subagents-always-acceptedits|CLD-C003]]** permission mode does not contain a workflow — hooks do
- **[[CLD-C005_forks-always-inherit-driver-model|CLD-C005]]** forks cannot be model-pinned, ever
- **[[CLD-C008_subagent-model-envvar-overrides-all-pins|CLD-C008]]** one env var voids an entire model-tier matrix
- **[[CLD-C013_file-permission-rules-only-edit-and-read|CLD-C013]]** only Edit(path)/Read(path) file permission rules are consulted — Write/MultiEdit/NotebookEdit/Glob path rules silently no-op
- **[[CLD-C015_workflow-agent-unpinned-inherits-session-model|CLD-C015]]** an unpinned workflow `agent()` inherits the session tier — pin every agent or the pin-gate blocks the run
- **[[CLD-C016_auto-memory-keys-one-store-per-repo-root|CLD-C016]]** auto-memory is ONE store per git-repo-root — no per-project isolation inside a repo without the `autoMemoryDirectory` redirect
- **[[CLD-C017_plugin-agenttypes-register-namespace-qualified|CLD-C017]]** plugin-bundled agents only resolve namespace-qualified (`<plugin>:<agent>`) — bare agentTypes miss the registry; mid-session installs register next session
- **[[CLD-C019_ask-rules-fail-closed-without-an-answerer|CLD-C019]]** a `permissions.ask` rule needs an answerer: interactively it reaches the owner through the PARENT session UI even for subagent calls, so ask rules GATE rather than hard-block; with no answerer (headless `claude -p`, CI, cron) it fails closed, and `acceptEdits` does not satisfy it
- **[[PY-C001_fstring-ast-offsets-are-expression-relative|PY-C001]]** below CPython 3.12, AST positions inside an f-string are expression-relative and `col_offset` is a BYTE offset, so span-based source rewriting corrupts files silently. Parse the result and refuse to write on error
- **[[PY-C002_set-plus-stable-sort-is-nondeterministic|PY-C002]]** sorting a `set` without a total tiebreak is not reproducible, which removes regenerate-and-diff as a verification technique. Fingerprint across several `PYTHONHASHSEED` values, never a single re-run
- **[[GIT-C001_macos-ignorecase-makes-gitignore-case-insensitive|GIT-C001]]** on macOS `.gitignore` matching is CASE-INSENSITIVE, so a data-exclusion glob can silently exclude intended source and the commit still succeeds. Root-anchor patterns and verify both directions with `git check-ignore -v`
- **[[CLD-C018_pretooluse-hooks-never-run-for-subagent-calls|CLD-C018]]** `PreToolUse` hooks never run for subagent tool calls — the entire protected-path hook scheme is absent inside subagents; only permission rules and `tools` scoping gate them
- **[[CLD-C022_output-style-frontmatter-ignores-unknown-keys|CLD-C022]]** output-style frontmatter honours 4 fields and silently drops the rest, so an output style can configure no behaviour. Config belongs in a settings file and is verified by reading back the effective key, not by finding the text somewhere
- **[[CLD-C023_plugin-project-scope-writes-three-artifacts|CLD-C023]]** a project-scoped plugin install writes THREE artifacts and resolves "project" to the GIT TOPLEVEL, one of them a repo-root `.claude/settings.json` the harness calls "shared with your team"; `marketplace remove` leaves the cache, and `enabledPlugins` is not the inventory. Baseline five axes, uninstall before deregistering, delete the cache by hand
- **[[CLD-C024_unindexed-memory-files-are-still-recallable|CLD-C024]]** (**QUALIFIED by [[CLD-C027_on-demand-memory-recall-is-remotely-feature-gated|CLD-C027]]: the path below is GATED OFF on this machine**) a memory topic file with no `MEMORY.md` index line is STILL recallable, because a second path enumerates the store directory and excludes only `MEMORY.md` itself, ranking on each file's own `description:`. An index line buys unconditional presence, not reachability, so de-indexing is not disposal and deleting is; and relocating pointers does not orphan their files
- **[[CLD-C025_subagent-memory-field-auto-enables-write-tools|CLD-C025]]** declaring `memory:` on a subagent auto-enables Read, Write and Edit regardless of its `tools:` list, so a read-only tier is widened invisibly and no YAML parse can detect it; the field is simultaneously inert whenever auto memory is off
- **[[CLD-C026_project-key-encoding-is-lossy-and-not-invertible|CLD-C026]]** a project key under `~/.claude/projects/` maps `/`, `_`, space and `.` ALL to a single `-`, so the encoding is lossy and cannot be inverted by substitution. A wrong decode names a path that does not exist and therefore reads as proof of an orphaned store: that exact mistake produced a recorded defect row and a remediation item proposing disposal of live content. Resolve a key by walking the filesystem, never by replacing `-` with `/`
- **[[CLD-C027_on-demand-memory-recall-is-remotely-feature-gated|CLD-C027]]** on-demand memory recall does not run unless a server-evaluated flag says so. `startRelevantMemoryPrefetch` returns before doing any work unless `tengu_moth_copse` is true or `CLAUDE_MEMORY_STORES` is set, and every local override entry point is an inert no-op, so an operator cannot turn it on. Measured false and unset 2026-09-02. Consequence: the always-on `MEMORY.md` load is the ONLY automatic surfacing channel, de-indexing removes reach rather than downgrading it, and any experiment measuring recall latency or relevance has no referent while the gate is off, so its negative result is NOT ENABLED and must never be scored as a failure
- **[[CLD-C028_project-key-resolution-is-not-single-valued|CLD-C028]]** project-key resolution is not single-valued: three resolvers coexist in one binary and disagree about the same inputs, and the harness itself ships `qRr(e)` to report the gap between two of them. The encoder is separately lossy twice over, collapsing `/`, space, `_`, `.` and `-` to one `-` and truncating past 200 characters with an unreproducible base-36 hash. Consequence: no tool may compute a key once and trust it, no check may decode a key by substitution (both error directions were observed, and the false-orphan direction has now produced a wrong finding twice), and any instrument naming a resolved store must name its resolver and declare the branches it cannot see
- **[[JIRA-C001_jira-tools-silently-return-confluence-results|JIRA-C001]]** the Atlassian connector's Jira tools can silently return Confluence objects — getVisibleJiraProjects yields spaces, and literal-email JQL falls back to a Confluence keyword search that looks like results. Filter with currentUser()/accountId and assert issue shape (key/issuetype/status) before use
- **[[CLD-C029_hook-ask-on-unparseable-bash-can-pass-without-prompt|CLD-C029]]** (**SUPERSEDED by [[CLD-C030_permission-prompts-are-recorded-only-in-the-desktop-app-log|CLD-C030]]: both asks reached the permission dialog and were answered, per the desktop app log**) in auto mode a hook's `ask` on a Bash command the harness cannot parse (a heredoc, for example) can resolve with no prompt: two tripwire asks never reached the owner and both commands ran, while every probe sent one call at a time prompted. Make protected writes through Edit or Write backed by `Edit(path)` ask rules, and treat the Bash tripwire as detection, not a checkpoint
- **[[CLD-C030_permission-prompts-are-recorded-only-in-the-desktop-app-log|CLD-C030]]** the session transcript records neither a permission prompt nor its answer; in the desktop app only `~/Library/Logs/Claude/main.log` does, one request line and one decision line per prompt. A gate check built on recollection or call timing is not a check: that method produced two false findings on 2026-09-15 (F33 and CLD-C029), both contradicted by the log. Pair request and decision lines by id, with a fixed hands-off interval before answering
- **[[RMK-C001_official-import-is-pdf-and-epub-only|RMK-C001]]** a reMarkable officially imports PDF and EPUB only, so sending markdown or any other text means either a converted reading document or a native notebook through the undocumented sync protocol. Decide which at the start
- **[[RMK-C002_developer-mode-factory-resets-and-breaks-secure-boot|RMK-C002]]** SSH on a Paper Pro requires developer mode, which FACTORY-RESETS the device, breaks the secure-boot chain, adds a permanent boot warning and ends vendor support. Prefer the cloud or USB paths
- **[[RMK-C003_sync-v3-write-replaces-the-account-wide-root-index|RMK-C003]]** adding ONE document through sync v3 replaces the ACCOUNT-WIDE root index, so a client that skips a line it cannot parse deletes that document from the whole library. Require a fail-closed parser, verbatim re-emission and a recorded previous root hash
- **[[RMK-C004_document-api-returns-401-to-a-browser-paired-device-token|RMK-C004]]** the reMarkable document API answers 401 to a browser-paired device token EVEN WITH Connect active, so such a client cannot create folders or delete what it pushed, and the client's "token expired" message is wrong. Do not re-pair; target an existing folder by id, and let the owner delete in the vendor app
