**Constraint:** `claude plugin install --scope project` writes THREE artifacts, not one, and "project" resolves to the **git toplevel** rather than the working directory: an entry in `~/.claude/plugins/installed_plugins.json`, a version-keyed cache under `~/.claude/plugins/cache/<marketplace>/`, and a `.claude/settings.json` created at the git toplevel that the harness itself describes as "shared with your team". Reversal is equally incomplete: `claude plugin marketplace remove` cascades to the install record but leaves the cache directory standing. Separately, `installed_plugins.json` and `enabledPlugins` are NOT a complete inventory of what is live in a session.

**Design consequence:** A scoped, reversible plugin trial is neither by default. The third artifact is a committable file at the repository root that the harness frames as team-shared, so a personal evaluation inside a shared repository can be committed to colleagues without the installer ever seeing the file. In a multi-project vault or monorepo, git-toplevel resolution silently widens the blast radius from one project folder to every project in the tree. Because reversal by the documented commands leaves cache residue, a post-uninstall baseline check that counts only install records reports clean while state persists on disk; a correct baseline needs five axes, not one. And because the live inventory exceeds the recorded one, no audit, security scan, or governance review built on `installed_plugins.json` can enumerate what is actually executing, which also bounds what any filesystem scan of `~/.claude` can reach. Compounding, per [[CLD-C017_plugin-agenttypes-register-namespace-qualified]]: plugin resources bind at session start, verified here for SKILLS as well as agents, so a plugin installed in order to run one of its tools cannot run that tool in the installing session.

**Sanctioned workarounds:** Before installing, record the baseline on five axes: install-record count, marketplace-file count, marketplaces-directory count, cache-directory count, and a grep of `~/.claude/settings.json` for the marketplace name. Confirm `git rev-parse --show-toplevel` is the scope actually intended, and check for a git-toplevel `.claude/settings.json` both before and after. Uninstall FIRST and deregister the marketplace SECOND, never in one command: the first can fail while the second succeeds, leaving an install record pointing at a removed marketplace. Delete the cache directory by hand as a required step, not an optional one, then re-verify all five axes against the recorded baseline. Treat any mid-session install as next-session-effective and plan a fresh session for the work. Never treat `enabledPlugins` as the inventory; enumerate what is live from the session's own available-resource listing instead.
